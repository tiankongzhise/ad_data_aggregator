## 广告数据聚合平台开发计划与排期（基于 PRD V1.1 & 技术框架）

### 一、项目概述
- **项目周期**：6 周（30 个工作日），建议投入 1 名后端 + 1 名前端 + 0.5 名测试/运维（可复用）
- **里程碑**：M1 后端核心能力（插件、调度、执行器）→ M2 前端管理界面 → M3 联调与生产就绪
- **风险缓冲**：每个阶段预留 10%~15% 时间处理集成问题、第三方 API 调试

---

### 二、阶段划分与任务分解

#### **阶段 0：环境搭建与技术预研（1.5 天）**
| 任务 | 产出 | 负责人 | 工时 |
|------|------|--------|------|
| 搭建后端开发环境（Python 虚拟环境、依赖安装、配置管理） | 可运行 FastAPI 空项目 | 后端 | 0.5d |
| 搭建前端开发环境（Vue3 + Vite + Element Plus） | 可访问的空白 SPA | 前端 | 0.5d |
| 准备数据库（MySQL/PostgreSQL 本地或 Docker） | 数据库实例 | 后端 | 0.2d |
| 确认各广告平台 API 文档可用性，申请测试账号 | 测试用 API Key | 后端 | 0.3d |

#### **阶段 1：数据库设计与基础模型（2 天）**
| 任务 | 产出 | 负责人 | 工时 |
|------|------|--------|------|
| 设计完整 ER 图（平台、报表、维度、指标、任务、数据记录、日志） | ER 图文档 | 后端 | 0.5d |
| 编写 SQLAlchemy ORM 模型（含索引、唯一约束） | 模型文件 | 后端 | 0.5d |
| 配置 Alembic 迁移脚本，初始化数据库 | 迁移文件、建表 | 后端 | 0.5d |
| 编写种子数据脚本（预置平台、报表结构示例） | seed.py | 后端 | 0.5d |

#### **阶段 2：后端核心模块开发（10 天）**
| 子模块 | 任务 | 产出 | 工时 |
|--------|------|------|------|
| **插件框架** (2d) | 1. 实现 `PlatformPlugin` 抽象基类<br>2. 实现插件注册表（工厂模式）<br>3. 实现巨量引擎插件（含真实 API 调用示例）<br>4. 实现腾讯广告插件（mock 优先，可后续替换） | `plugins/` 目录，至少 2 个插件 | 2d |
| **数据层仓库** (1.5d) | 1. 实现 `BaseRepository`（通用 CRUD + upsert 方言适配）<br>2. 实现 `DataRepository`（数据记录 upsert）<br>3. 实现任务、日志仓库 | `repositories/` | 1.5d |
| **调度器模块** (2d) | 1. 实现抽象锁接口 + 单机内存锁<br>2. 集成 `AsyncIOScheduler`，支持从数据库加载任务<br>3. 实现动态增删改任务（任务变更时刷新调度器）<br>4. 实现时间分区工具（日报/小时报） | `scheduler/` | 2d |
| **执行器模块** (2.5d) | 1. 实现 `runner.py` 核心执行逻辑（调用插件 → 转换 → upsert）<br>2. 集成 tenacity 指数退避重试<br>3. 实现平台级限流（`asyncio.Semaphore`）<br>4. 实现数据转换器（各平台原始数据 → 统一中间格式） | `executor/` | 2.5d |
| **告警模块** (1d) | 1. 企业微信 webhook 告警<br>2. 邮件告警（smtplib）<br>3. 告警管理器（统一入口） | `alerting/` | 1d |
| **REST API 实现** (1d) | 1. 平台配置接口（CRUD）<br>2. 任务管理接口（含手动触发）<br>3. 日志查询接口<br>4. 健康检查、Swagger 文档 | `api/v1/` 路由 | 1d |

> **阶段 2 完成标志**：可通过 API 创建任务、手动触发、数据入库、日志记录，且支持两个以上平台插件。

#### **阶段 3：前端界面开发（7 天）**
| 页面/模块 | 任务 | 产出 | 工时 |
|-----------|------|------|------|

| **平台配置页** (1.5d) | 1. 平台列表展示、增删改（软删除）<br>2. 报表树管理（添加/编辑报表）<br>3. 维度/指标动态表单（支持增删字段） | `PlatformConfig.vue` | 1.5d |
| **任务管理页** (2.5d) | 1. 任务列表（分页、筛选、状态切换）<br>2. 新建/编辑弹窗（平台联动报表、动态渲染维度/指标复选框）<br>3. 手动触发弹窗（日期范围限制≤7天）<br>4. 启用/禁用、删除操作 | `TaskManage.vue` + 子组件 | 2.5d |
| **日志查询页** (1d) | 1. 筛选栏（任务、时间范围、状态）<br>2. 日志列表表格<br>3. 详情抽屉（显示错误堆栈、重试次数） | `LogQuery.vue` | 1d |
| **状态管理与优化** (1d) | 1. Pinia 存储（任务列表缓存、平台元数据）<br>2. 全局错误处理、加载状态<br>3. 手动触发后的轮询/反馈优化 | `stores/`, 全局组件 | 1d |

### 五、风险与应对措施

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|----------|
| 广告平台 API 文档不准确或认证复杂 | 高 | 延长插件开发时间 | 优先实现 mock 版本，保证框架可运行；真实对接作为独立任务并行 |
| 不同平台数据字段差异过大，转换逻辑复杂 | 中 | 数据转换器反复修改 | 设计灵活中间格式（JSON 字段），先保证核心字段映射，非核心字段存储原始 JSON |
| 调度器分布式锁预留需求突然要求上线 | 低 | 需替换锁实现 | 已预留抽象接口，只需实现 Redis 版并切换配置，代码改动量小 |
| 前端动态表单（维度/指标）性能问题 | 低 | 页面卡顿 | 使用虚拟滚动或分步加载，限制单报表维度/指标数量 ≤50 |
| 手动触发大量历史数据导致后端 OOM | 中 | 服务崩溃 | 执行器增加批次拆分（如每次只拉取 7 天），并通过信号量控制并发 |

### 六、验收标准（DoD）

- **后端**：
  - [ ] 所有 API 通过 Postman 测试并提供 Swagger 文档
  - [ ] 插件可独立扩展，新增平台无需修改核心代码
  - [ ] 任务失败后指数退避重试，且限流机制生效
  - [ ] 数据记录唯一约束（platform+report+data_time+dimension_hash）有效防止重复
- **前端**：
  - [ ] 平台配置、任务管理、日志查询三个核心页面功能完整
  - [ ] 任务表单联动正确，手动触发日期范围限制生效
  - [ ] 错误提示友好，无控制台报错
- **运维**：
  - [ ] 提供一键部署脚本（Docker Compose 可选）
  - [ ] 监控指标（Prometheus）暴露，告警规则配置
