## 二、后端技术框架（Python）

### 2.1 技术栈选型

| 类别 | 技术 | 说明 |
|------|------|------|
| Web 框架 | **FastAPI** | 高性能、异步支持、自动 OpenAPI 文档，便于前后端联调 |
| 异步任务 / 调度 | **APScheduler** (BackgroundScheduler) + 可选 Celery | MVP 单机使用 APScheduler；锁接口抽象，后续可无缝换 Redis 分布式锁 |
| ORM | **SQLAlchemy 2.0** (异步) | 支持 MySQL/PostgreSQL，提供 Alembic 做迁移 |
| 数据库驱动 | asyncmy (MySQL) / asyncpg (PostgreSQL) | 异步驱动 |

| 重试库 | **tenacity** | 实现指数退避重试，用于 API 调用和数据库重连 |
| HTTP 客户端 | **httpx** (异步) | 调用各广告平台 API，支持超时、重试拦截器 |
| 告警 | **requests** / httpx | 调用企业微信/钉钉 webhook，发送邮件 (smtplib) |
| 加密 | **cryptography** (Fernet) | 加密存储 API 密钥等敏感信息 |
| 配置管理 | **pydantic-settings** | 支持 `.env` 和环境变量，区分开发/生产 |
| 日志 | **loguru** | 结构化日志，自动滚动，保留 30 天 |
| 可观测性 (可选) | **prometheus-fastapi-instrumentator** | 暴露 /metrics 供 Prometheus 抓取 |
| 进程管理 | **supervisor** 或 systemd | 生产环境守护进程 |

### 2.3 关键接口与实现要点

#### 2.3.1 插件接口（`plugins/base.py`）

```python
from abc import ABC, abstractmethod
from typing import List, Dict, Any
from datetime import date, datetime

class PlatformPlugin(ABC):
    """所有广告平台插件必须实现的接口"""
    
    @abstractmethod
    async def fetch_data(
        self,
        credentials: Dict[str, str],   # 解密后的API密钥等
        report_type: str,              # 如 "ad_plan_daily"
        dimensions: List[str],         # ["date", "plan_id"]
        metrics: List[str],            # ["cost", "click"]
        start_time: datetime,          # 数据起始时间（已转换为平台时区）
        end_time: datetime,
    ) -> List[Dict[str, Any]]:
        """
        调用平台API，返回原始数据列表。
        每个dict包含维度字段和指标字段，字段名保持平台原始命名。
        """
        pass
    
    @abstractmethod
    def get_platform_name(self) -> str:
        pass
```

#### 2.3.2 统一数据存储模型（`models/data_record.py`）

```python
from sqlalchemy import Column, String, DateTime, BigInteger, JSON, Index
from sqlalchemy.dialects.mysql import BIGINT
from .base import Base

class DataRecord(Base):
    __tablename__ = "ad_data_records"
    
    id = Column(BigInteger, primary_key=True, autoincrement=True)
    # 业务唯一键组成部分（冗余存储便于查询，实际唯一约束由组合hash保证）
    platform = Column(String(64), nullable=False)
    report = Column(String(128), nullable=False)
    data_time = Column(DateTime, nullable=False)          # 数据所属时间（天或小时）
    dimension_hash = Column(String(64), nullable=False)   # 各维度值组合的hash
    dimensions = Column(JSON, nullable=False)             # 存储维度键值对，如 {"plan_id": "123"}
    metrics = Column(JSON, nullable=False)                # 存储指标键值对，如 {"cost": 10.5}
    source_type = Column(String(32), nullable=False)      # "日报" / "小时报" / "手动获取" / "unknown"
    fetched_at = Column(DateTime, nullable=False)         # 拉取时间
    created_at = Column(DateTime, server_default="CURRENT_TIMESTAMP")
    updated_at = Column(DateTime, onupdate="CURRENT_TIMESTAMP")
    
    # 唯一约束：平台+报表+数据时间+维度hash（不含source_type）
    __table_args__ = (
        Index("uk_data", "platform", "report", "data_time", "dimension_hash", unique=True),
    )
```

#### 2.3.3 Upsert 仓库层实现（`repositories/data_repo.py`）

使用 SQLAlchemy 的 `on_conflict_do_update` (PostgreSQL) 或 `INSERT ... ON DUPLICATE KEY UPDATE` (MySQL)，封装为方言兼容方法。

#### 2.3.4 调度器集成（`scheduler/manager.py`）

- 使用 `AsyncIOScheduler`（配合 FastAPI 生命周期）
- 启动时从数据库加载所有启用任务，动态添加 job
- 监听任务变更（创建/编辑/启停），实时更新调度器
- 任务锁抽象：`TaskLocker` 接口，单机实现使用 `asyncio.Lock` 字典；Redis 实现预留

#### 2.3.5 执行器与重试（`executor/runner.py`）

```python
@retry(
    stop=stop_after_attempt(5),
    wait=wait_exponential(multiplier=1, min=60, max=960),  # 1,2,4,8,16分钟
    retry=retry_if_exception_type(ApiLimitError, NetworkTimeoutError),
    before_sleep=before_sleep_log(logger, logging.WARNING)
)
async def run_task(task_id: int, time_range: Tuple[datetime, datetime], source_type: str):
    ...
```

#### 2.3.6 平台级限流

使用 `asyncio.Semaphore` 针对每个平台创建独立的信号量，数量由配置 `platform_concurrency[platform]` 决定。

### 3.3 核心页面功能点

## 五、开发与部署建议

1. **后端启动顺序**：
   - 运行 `alembic upgrade head` 初始化数据库
   - 预置基础数据（如平台、报表等，通过 seed 脚本）
   - 启动 FastAPI：`uvicorn src.main:app --host 0.0.0.0 --port 8000`

2. **调度器生命周期**：
   - 在 FastAPI 的 `lifespan` 上下文管理中启动和关闭 APScheduler
   - 确保应用退出时正确关闭调度器，避免僵尸作业

3. **插件热加载**（可选）：
   - 使用 `importlib` 动态扫描 `plugins/` 目录，实现新增平台无需重启

4. **前端环境变量**：
   - `.env.development` 中配置 `VITE_API_BASE_URL=http://localhost:8000/api/v1`

5. **测试策略**：
   - 后端：pytest + 异步测试（`pytest-asyncio`），mock 外部 API
   - 前端：Vitest + Vue Test Utils，重点测试任务表单的动态联动

6. **监控告警落地**：
   - 后端集成 `prometheus-fastapi-instrumentator`，暴露 `task_execution_total`、`task_duration_seconds` 等指标
   - 告警规则：任务失败率 > 10% 触发 Alertmanager

## 六、PRD 关键约束落地检查

| PRD 要求 | 框架实现方式 |
|----------|--------------|
| 插件化设计 | `PlatformPlugin` 抽象类 + 注册表，调度/执行器不感知具体平台 |
| 业务唯一键不含来源方式 | `DataRecord` 模型的唯一约束不含 `source_type` |
| 指数退避重试 | `tenacity` 配置固定退避策略 |
| 平台级限流 | `asyncio.Semaphore` 按平台名称隔离 |
| 锁接口抽象 | `core/task_locker.py` 提供抽象类，单机内存实现，可插拔 Redis |
| ORM 封装 upsert | `repositories/base_repo.py` 实现 `upsert` 方法，根据数据库方言适配 |
| 历史数据初始化 | 单独脚本 `scripts/backfill.py`，复用 `executor.runner` 逻辑 |
| 告警配置无界面 | 通过 `.env` 配置，代码直接读取 |
