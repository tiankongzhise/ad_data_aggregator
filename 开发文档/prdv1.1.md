## 2. 产品概述

### 2.1 产品背景
公司需要从多个广告平台（巨量引擎、腾讯广告、百度营销等）自动化采集广告投放数据，存入统一的数据存储中，为下游ETL、数据分析、报表展示提供可靠、标准化的源数据。当前面临各平台API差异大、手工维护成本高、数据难以复用等问题。

### 2.2 目标用户
- **直接用户**：下游数据中台 / 数据仓库（系统间调用，无人工界面）
- **间接用户**：数据运维人员（配置任务、查看日志）、数据分析师（消费统一数据）

### 2.3 价值主张
- **可扩展性**：插件化设计，新增广告平台无需修改核心逻辑
- **统一数据模型**：将异构平台数据转换为标准格式，并标记来源方式
- **灵活调度**：支持按天/小时定时采集 + 手动拉取，upsert保证数据一致性
- **运维友好**：内置任务日志、指数退避重试、失败告警（企业微信/邮件等）

## 3. 功能需求（按用户故事拆分）

### 3.1 管理员配置管理（后台）
**用户故事**：作为管理员，我希望配置每个广告平台支持的报表、维度、指标及其关联关系，以便后续用户创建采集任务时动态选择。

- **场景**：新增一个广告平台或平台升级API后，需要更新元数据
- **前置条件**：用户具有管理员权限
- **操作步骤**：
  1. 进入“平台管理”界面
  2. 选择或新增平台（巨量引擎/腾讯广告/百度营销）
  3. 配置该平台下的报表（如“广告计划报表”“广告组报表”）
  4. 为每个报表配置可用的维度列表（如时间、计划ID、地域等）
  5. 为每个报表配置可用的指标列表（如消耗、点击量、转化数等），并关联数据类型
  6. 保存配置
- **预期结果**：用户在创建采集任务时，选择平台和报表后，维度/指标下拉框仅显示已配置的合法选项。
- **优先级**：P0（核心前置功能）

### 3.2 用户创建采集任务
**用户故事**：作为数据运维人员，我希望为一个平台的一个报表创建采集任务，指定拉取频率（按天/按小时）、时间范围、维度和指标，并设置调度启停。

- **场景**：需要定时拉取巨量引擎的“广告计划日报”
- **前置条件**：平台及报表已在后台配置
- **操作步骤**：
  1. 进入“任务管理”页面，点击“新建任务”
  2. 选择平台、报表
  3. 根据所选报表动态展示维度复选框和指标复选框（灰色不可选表示不适用）
  4. 选择采集频率：按天 / 按小时 / 仅手动（定时关闭）
  5. 设置默认拉取的时间范围（如近7天），运行时支持手动指定
  6. 配置任务启用状态（默认启用）
  7. 保存任务
- **预期结果**：任务保存至数据库，调度器根据频率自动触发；若为“仅手动”，则只有手动触发有效。
- **优先级**：P0

### 3.3 系统自动调度采集（核心流程）
**用户故事**：作为系统，我需要按照任务的频率（按天/按小时）自动执行数据拉取，调用对应平台API，通过ORM将数据 upsert 到数据库，并记录每条数据的来源方式。

- **场景**：每天凌晨2点自动拉取所有启用中的日报任务
- **前置条件**：任务已启用，且配置了合法的维度和指标
- **操作步骤**：
  1. 调度器唤醒，筛选出当前时间点需要执行的任务（如日报任务在每天02:00执行，小时报任务在每小时第5分钟执行）
  2. 对每个任务，确定拉取的时间分区：
     - 日报：拉取前一个自然日的数据
     - 小时报：拉取前一个完整小时的数据（如当前时间09:10，拉取08:00-08:59）
  3. 调用对应广告平台API插件，传入认证信息、维度、指标、时间范围
  4. 解析API返回数据，转换为统一中间格式（包含字段：数据来源方式、平台、报表、拉取时间、数据时间、各维度值、各指标值）
  5. 对每条数据，基于业务唯一键（**不含来源方式**，详见5.6）执行 upsert：
     - 若键不存在，插入新记录
     - 若键已存在，更新指标值（覆盖）
  6. 记录任务执行日志（开始时间、结束时间、拉取记录数、状态）
  7. 若失败，按指数退避策略重试（见非功能需求），最终失败则标记任务失败并触发告警
- **预期结果**：数据库中保存最新数据，无重复；任务日志可追溯。
- **优先级**：P0

### 3.4 手动拉取数据
**用户故事**：作为数据运维人员，我希望能够临时手动触发一个任务，指定任意时间范围（如近3天），立即拉取数据，并同样遵循 upsert 规则，同时记录来源方式为“手动获取”。

- **场景**：发现某天数据缺失，需要补拉；或测试新配置的维度和指标
- **前置条件**：任务已存在
- **操作步骤**：
  1. 在任务管理页面，点击某任务的“手动执行”按钮
  2. 弹出时间范围选择器（默认近3天，可自定义起始日期）
  3. 点击确认
  4. 系统异步执行拉取流程（同3.3步骤，但来源方式标记为“手动获取”）
  5. 页面显示“任务已提交”，用户可在日志页面查看执行结果
- **预期结果**：指定时间范围内的数据被拉取或更新，且来源方式区分于定时任务。
- **优先级**：P1

### 3.5 任务调度管理（启用/禁用/编辑/删除）
**用户故事**：作为数据运维人员，我希望能够随时启用、禁用、编辑或删除一个采集任务，禁用后调度器不再触发该任务。

- **场景**：某个广告平台API升级，需临时停用任务；或调整任务频率
- **前置条件**：任务已存在
- **操作步骤**：
  1. 任务列表中切换“启用/禁用”开关
  2. 编辑任务时，可修改频率、维度和指标（但不可变更平台和报表，若需变更，建议新建任务）
  3. 删除任务时，二次确认后软删除（保留日志）
- **预期结果**：任务状态实时生效；调度器下次轮询时跳过禁用任务。
- **优先级**：P1

### 3.6 执行日志查看与告警
**用户故事**：作为数据运维人员，我希望能够查看每次任务执行的详细日志，并在任务失败时通过企业微信/邮件收到告警，以便及时处理问题。

- **场景**：任务失败需要排查原因；收到告警后快速介入
- **前置条件**：日志已记录，告警渠道已配置（通过配置文件）
- **操作步骤**：
  1. 进入“日志管理”页面，可按任务、时间范围、状态筛选
  2. 点击某条日志可查看详情：开始/结束时间、耗时、拉取记录数、错误堆栈（如有）
  3. 系统在任务最终失败后（重试耗尽），发送告警到配置的webhook（企业微信/钉钉）或邮件地址
- **预期结果**：日志完整可查，告警及时通知。
- **优先级**：P1

## 4. 业务流程（文字描述）

### 4.1 数据采集整体流程
```text
[管理员] → 配置平台/报表/维度/指标
   ↓
[运维] → 创建采集任务（指定平台、报表、频率、维度、指标）
   ↓
[调度器] → 定期扫描启用任务 → 根据频率触发
   ↓
[执行器] → 调用平台API插件 → 获取数据 → 转换为统一格式（附来源方式）
   ↓
[ORM层] → upsert到MySQL/PostgreSQL（基于业务唯一键，不含来源方式）
   ↓
[日志模块] → 记录执行结果 → 若失败则指数退避重试 → 最终失败告警
```

### 4.2 手动补拉流程
```text
[运维] → 任务列表点击“手动执行” → 指定时间范围
   ↓
[系统] → 异步执行（复用拉取逻辑，来源方式=手动获取）
   ↓
[日志] → 记录手动执行结果
```

## 5. 非功能性需求

| 类别 | 具体要求 |
|------|----------|
| 性能 | 单个任务拉取10万条数据（约5MB）应在2分钟内完成；支持并发执行多个平台任务（可配置最大并发数，如5）；**同平台受平台级限流配置**（如QPS上限），不同平台可并发 |
| 可扩展性 | 新增广告平台只需实现统一的 `PlatformPlugin` 接口（认证、请求、解析），无需修改调度和存储逻辑 |
| 可靠性 | 任务失败采用指数退避重试：第1次延迟1分钟，第2次2分钟，第3次4分钟，第4次8分钟，第5次16分钟，最多5次；重试期间任务状态为“重试中”；5次失败后标记为“失败”并告警 |
| 数据一致性 | upsert基于业务唯一键：**平台 + 报表 + 数据时间（精确到天或小时） + 各维度值的组合hash**（不包含来源方式）；手动拉取与定时拉取共享同一逻辑，保证幂等 |
| 安全性 | API密钥等敏感信息加密存储（如AES），数据库连接使用安全凭证；系统内部仅开放必要端口；日志中不打印明文密钥 |
| 兼容性 | 使用SQLAlchemy ORM，支持MySQL 5.7+ / PostgreSQL 12+；可配置连接池；**upsert实现封装在仓库层**，对上层透明 |
| 可观测性 | 提供Prometheus指标（任务执行次数、成功率、耗时）可选；日志按天滚动，保留30天 |
| 调度精度 | 按小时任务允许误差±5分钟；按天任务指定时间点（如02:00）执行；支持时区配置（默认UTC+8） |
| 锁机制 | **单机调度**（MVP），但锁接口需抽象（如 `TaskLocker`），后续可无缝升级为Redis分布式锁，避免多实例重复执行 |

## 6. 边界与异常说明

| 场景 | 处理方式 |
|------|----------|
| API限流（429/403） | 捕获限流异常，按指数退避重试；若持续失败，记录错误并告警 |
| API返回空数据 | 视为正常，不报错，日志中记录拉取0条 |
| 网络超时 | 设置API请求超时30秒，超时后进入重试流程 |
| 任务正在执行中又被触发 | 加任务级互斥锁（通过抽象锁接口），跳过本次触发，记录警告日志 |
| 数据库连接失败 | 重试3次（间隔5秒），仍失败则任务失败并告警 |
| 手动拉取时间范围过大 | 限制单次最大7天，若需更大范围，拆分为多次手动执行或调整任务默认范围 |
| 维度/指标组合不合法 | 平台API可能会返回错误，系统捕获后标记任务失败，提示“平台返回错误：不支持的维度组合” |
| 任务删除时仍有运行中的实例 | 等待当前实例执行完毕后再删除（软删除后禁止新触发） |
| 来源方式字段缺失 | 在写入数据库前强制赋值，若来源不明则标记为“unknown” |
| 历史数据初始化 | **不在本系统自动处理**；由单独的脚本（或手动任务）按需补拉 |

## 7. 验收标准

1. **配置管理**：管理员能成功配置巨量引擎的“广告计划日报”报表，并关联维度（日期、计划ID）和指标（消耗、点击量）。用户创建任务时，选择该报表后维度/指标下拉框仅显示上述选项。
2. **定时调度**：创建按天02:00执行的任务，第二天02:05后检查数据库，应有前一日的数据且来源方式为“日报”。创建按小时任务，在下一小时的第10分钟内触发成功，数据来源方式为“小时报”。
3. **手动拉取**：手动触发某任务，指定时间范围2026-04-01至2026-04-03，数据写入数据库且来源方式为“手动获取”。再次手动拉取相同时间范围，数据应被更新而非重复插入（upsert验证）。
4. **重试与告警**：模拟API返回500错误，观察系统按1分钟、2分钟、4分钟…重试5次，最终失败后发送告警到配置的webhook。
5. **扩展性**：新增一个模拟平台插件（如“Demo Platform”），实现统一接口，无需修改调度和存储代码即可正常工作。
6. **日志**：所有任务执行记录（含手动触发）在日志页面可查，包含拉取记录数和错误详情。
7. **数据唯一性**：数据库中不存在因重复拉取产生的完全重复记录（相同唯一键只有一条）。唯一键不包含来源方式，因此日报和手动拉取同一天的数据会互相覆盖（符合预期）。
8. **锁抽象**：代码中存在 `TaskLocker` 接口，且单机实现可用；通过配置可切换为Redis实现。
9. **平台限流**：同平台同时执行的任务数不超过配置的限流值（如2个），不同平台可并发。
